# Description

The goal of this project is to dive into the world of containers and their interactions; indeed, Docker is essential nowadays.

The main purpose of Docker is to be able to run applications on any machine, OS, or architecture, by emulating micro-environments inside containers.

An application is then split into microservices, each in its own container, communicating with each other through a private Docker network, and made available on the host machine through port forwarding.

This project is accessible from a KVM (Kernel Virtual Machine), i.e. a virtual machine running on a type 1 hypervisor — a hypervisor that performs virtualization directly from the kernel — whereas a type 2 hypervisor would be an application running on top of our OS. The performance of a KVM is close to the real performance of our host machine.

The mandatory part of Inception requires us to create 3 containers connected together in a private network:

- **MariaDB**: a database used to store WordPress data
- **WordPress + PHP-FPM**: Create and manage a website without needing to code: showcase site, blog, online shop, portfolio (CMS – Content Management System). PHP-FPM generates the static pages from the requests forwarded by Nginx.
- **Nginx**: Web server that serves static files and acts as a reverse proxy to redirect external requests through configurable routes to the applications and services in our containers; the static pages will have been generated by PHP-FPM in the WordPress container.

To validate the project, the connection must be secured with HTTPS (port 443) using certification keys that can be self-generated for the project. After configuring our Docker setup, WordPress will be accessible at: https://thmaitre.42.fr


### Using Docker

Start the Docker containers:

```bash
docker compose up -d --build
```

with Makefile:

```bash
make
```

Stop the containers:

```bash
docker compose down
```

with Makefile:

```bash
make down
```

Other useful commands:

|Command|Description|
|---|---|
|`docker logs [container]`|Display the logs|
|`docker volume ls`|List the volumes|
|`docker volume rm [volume]`|Remove a volume|
|`docker exec -it [container] [shell]`|Enter a container with a command line|

### Virtual Machines vs Docker

**Virtual machine:**

A virtual machine is a fully simulated machine, including the kernel and hardware drivers. There are two types of virtual machines. Virtual machines are managed by software called a hypervisor.

- **Type 1 hypervisor**: runs directly on the kernel, optimized; the performance of the host machine and the VM will be practically equivalent — this is the optimized version of virtual machines.
- **Type 2 hypervisor**: our host has an OS, which runs a hypervisor application, which in turn runs a virtual machine — much more resource-intensive.

**Docker:**

Docker was created in 2013 by Solomon Hykes. Unlike virtual machines, a Docker container does not include an operating system; it relies on operating system features provided by the host system. The advantage of Docker is that it allows you to create application containers isolated from one another, able to run on any machine in a lightweight, portable, and flexible way. AWS (Amazon Web Services) uses Docker and Kubernetes to handle connection demand to your server by spawning containers on the fly depending on demand, across a fleet of different machines.

### Secrets vs environment variables

Both are ways to parameterize our Docker configurations with environment variables.

- **Secrets**: will not be available in our container's logs and provide complete security if our containers were to be attacked.
- **Regular environment variables**: readable from inside the container and must never contain sensitive data.

> Obviously, neither of these two variable storage methods should ever be pushed to a GitHub repo.

### Docker Network vs Host Network

When Docker starts one or more containers, it has to decide how to connect them to the network.

**Docker network (bridge):**

Docker generates a virtual network (docker0); containers and services can communicate inside this network, and we can use port forwarding to 
redirect a port from our host to a port of one of our containers:

```bash
docker run -p 8080:80 nginx
```

Traffic arriving on port 8080 on our host machine will be redirected to port 80, used here by Nginx for an HTTP connection. We can also
create our own custom subnetworks.

**Host network:**

Here the network is directly shared with our host machine; applications launched in containers will be directly accessible from our host.
Useful for applications that require minimal latency, for network monitoring tools that need to observe all the host's ports, or for
applications that open many ports, which are harder to map. The host network is less safe than the bridge because it directly exposes our
services without isolation.

### Docker volumes vs bind mounts

Used to persist data beyond a container's life cycle. By default, everything a container writes to its file system is ephemeral.

- **Bind mount**: files are synchronized in real time between the host and the container. Useful during the development phase.
- **Docker volume**: Docker creates a storage space in its own internal directory `/var/lib/docker/volumes/`. This makes volumes portable
between machines. Better performance. Used in production / for databases.
